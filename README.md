# Telegram-бот учёта посещаемости

Одна учебная группа, Go, SQLite и Telegram webhook. Студент отмечает своё отсутствие до начала пары; староста управляет предметами, расписанием и доступом. Напоминания и экспорт в MVP не входят.

## Запуск

Нужен Go 1.23 или новее. Создайте бота через @BotFather и узнайте свой числовой Telegram ID.

```bash
cp .env.example .env
# Заполните .env своими значениями.
set -a
source .env
set +a
go run ./cmd/bot
```

Приложение проверяет конфигурацию, открывает SQLite, применяет встроенные SQL-миграции, проверяет публичный HTTPS `/health`, затем `getWebhookInfo` и регистрирует webhook. Без `WEBHOOK_URL` или при ошибке Telegram API запуск прекращается. Long polling не используется. Бинарный файл не зависит от текущего каталога миграций.

Настройки:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен @BotFather |
| `OWNER_TELEGRAM_ID` | Положительный ID владельца |
| `DATABASE_PATH` | Файл SQLite, например `./data/bot.db` |
| `GROUP_TIMEZONE` | `Europe/Minsk` по умолчанию |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error` |
| `WEBHOOK_URL` | Публичный базовый HTTPS URL без пути, например `https://bot.example.com` |
| `WEBHOOK_PATH_SECRET` | Случайная строка для пути, только латинские буквы, цифры, `_`, `-` |
| `WEBHOOK_SECRET_TOKEN` | Отдельная случайная строка для проверки заголовка Telegram |
| `HTTP_LISTEN_ADDR` | `:8080` по умолчанию |

Для каждого секрета можно использовать `openssl rand -hex 32`. Не коммитьте `.env`. Бот принимает сообщения и кнопки только в личном чате.

## HTTPS и локальная разработка

TLS завершается на внешнем reverse proxy или туннеле. Сам бот слушает HTTP. Прокси должен передавать POST `/webhook/<WEBHOOK_PATH_SECRET>` и заголовок `X-Telegram-Bot-Api-Secret-Token` без изменения. Эндпоинт `/health` проверяет доступность БД. Он должен быть доступен через публичный HTTPS адрес: при запуске приложение проверяет его с таймаутом.

Для разработки запустите, например:

```bash
cloudflared tunnel --url http://localhost:8080
# Или: ngrok http 8080
```

Впишите полученный HTTPS адрес в `WEBHOOK_URL`, загрузите `.env` и перезапустите приложение. Адрес должен быть доступен Telegram из интернета. Telegram не возвращает текущий секрет в `getWebhookInfo`, поэтому приложение повторно устанавливает webhook при каждом запуске, включая случай совпадения URL. Это позволяет менять секрет заголовка.

## Docker

```bash
docker compose up --build -d
docker compose logs -f bot
```

Порт опубликован на `127.0.0.1:8080` для локального reverse proxy или туннеля. Данные находятся в именованном volume `bot-data`, файл `/app/data/bot.db`. Контейнер работает от непривилегированного пользователя. `docker compose down` сохраняет volume; `down -v` удаляет данные. База часовых поясов встроена в бинарный файл через `time/tzdata`.

## Настройка через бота

1. Владелец отправляет `/start` и вводит название группы. Если группа уже существует, первоначальная настройка подключает владельца к ней.
2. Через `/admin` создаёт предметы и расписание. Диалог: предмет → день недели или конкретная дата → номер пары → время → итоговая карточка → «Сохранить». «Назад» и «Отмена» доступны на шагах. Изменение занятия проходит через те же шаги; удаление требует подтверждения.
3. В разделе «Код приглашения» получает код и передаёт его студентам. Замена кода не отключает участников.
4. Студент отправляет `/start`, вводит код и получает меню.
5. «Доступ и роли» позволяет отозвать и восстановить доступ. Только владелец назначает и снимает администраторов. Отозванный пользователь не может повторно подключиться кодом: администратор должен восстановить доступ.

Архивные предметы скрываются из выбора отметок. История сохраняется при удалении занятия. Название предмета в истории соответствует текущему названию.

## Команды и отметки

- `/start` — подключение, меню или продолжение сохранённого диалога.
- `/absent` — занятия сегодня, ещё не начавшиеся в часовом поясе группы.
- `/mystats` — история; кнопки изменения и отмены проверяют дедлайн повторно. Для изменения действуют актуальный и сохранённый исходный дедлайны; перенос начавшейся пары на более позднее время не открывает отметки снова.
- `/settings` — группа, роль, часовой пояс.
- `/admin` — управление для администратора и владельца.
- `/group` — статистика с выбором даты и предмета, список студентов и причины.
- `/help` — инструкция; `/cancel` — отмена текущего диалога.

Повторное сохранение отметки на то же занятие меняет её причину и комментарий. Одна запись на студента, предмет, дату и номер пары. Создание и изменение проверяют расписание и дедлайн внутри транзакции. В момент начала пары изменения уже запрещены. Для отмены сохраняется время начала исходного занятия, чтобы удаление расписания не позволило обходить дедлайн. Уважительная причина допускает необязательный комментарий до 500 символов.

Длинные списки разбиты по 10 записей; длинные сообщения разделяются на безопасные части. Сообщения используют обычный текст без Markdown/HTML. Состояние единственного активного диалога хранится в SQLite и восстанавливается через `/start` после перезапуска.

## Хранение и миграции

SQLite использует WAL, foreign keys, busy timeout и один connection. Все рабочие запросы получают `context.Context`. Связанные изменения и журнал административных действий сохраняются транзакционно; запросы к Telegram выполняются после транзакций. Логи структурированные (`slog`), без токенов и кодов приглашения.

Календарные даты хранятся как Unix seconds полуночи UTC, используемой как маркер календарного дня. Это не дедлайн: фактическое время начала рассчитывается из календарной даты, времени и часового пояса группы и сохраняется отдельно в `start_at`. Даты создания и изменения также Unix seconds.

Миграции применяются автоматически один раз, до запуска HTTP обработчиков. Миграция 000003 сохраняет прежние предметы, расписание и отметки, переводит даты в INTEGER и добавляет ограничения. Старые отметки получают `start_at=0`, поэтому их отмена блокируется: исходный дедлайн раньше не сохранялся. Старые черновики прежней незавершённой реализации могут потребовать `/cancel`. При некорректном или дублированном старом расписании миграция завершается ошибкой и откатывается; исправьте конфликтующие записи на копии базы перед обновлением.

Webhook проверяет метод, секретный заголовок, JSON и размер тела (1 MiB). Обновление сохраняется в SQLite до ответа `200`, затем обрабатывается последовательно фоновым worker. Уникальный `update_id` защищает от повторной доставки; незавершённые обновления остаются после перезапуска. Ошибки отправки в Telegram повторяются. При аварии между отправкой сообщения и подтверждением обработки Telegram может получить повторное сообщение: доставка в этой границе имеет семантику «как минимум один раз». Обработанные payload очищаются; идентификаторы остаются для дедупликации.

При SIGINT/SIGTERM прекращается приём HTTP запросов, завершается текущая обработка с ограниченным ожиданием и закрывается SQLite. Оставшиеся в очереди обновления обрабатываются после следующего запуска.

## Резервное копирование и восстановление

Для работающей SQLite используйте online backup, не копируйте один `.db` при активном WAL:

```bash
sqlite3 ./data/bot.db ".backup './backup.db'"
```

Для Docker остановите бот и скопируйте весь каталог данных, включая WAL/SHM, если они остались:

```bash
docker compose stop bot
docker compose cp bot:/app/data ./backup-data
docker compose start bot
```

Восстановление: остановите приложение, сохраните прежний каталог отдельно, замените каталог данных согласованной резервной копией и запустите бот. При восстановлении одиночного файла из `.backup` уберите прежние `bot.db-wal` и `bot.db-shm` из восстанавливаемого каталога. В Docker обеспечьте владельца файлов UID 10001. Версия приложения должна поддерживать миграции копии; автоматического отката схемы при запуске нет.

## Проверки

```bash
gofmt -w cmd internal pkg migrations/embed.go tests
go vet ./...
go test ./...
go build -o bot ./cmd/bot
```

Тесты используют реальные миграции и временные файловые SQLite базы, управляемое время и подмену HTTP Telegram API. Проверяют дедлайн точно в момент начала в Europe/Minsk, изменение/отмену/уникальность отметок, роли, отзыв доступа, чужую группу, одноразовое расписание, статистику, восстановление диалогов, webhook авторизацию/размер/дедупликацию и полный диалог от настройки до отметки.

Для проверки настоящего Telegram нужны реальные токен и публичный HTTPS endpoint: проверьте регистрацию webhook, доставку сообщений/кнопок и доступность URL снаружи.
